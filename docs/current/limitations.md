# Sanctum V1.2 release limitations

Sanctum V1.2.0 is **complete with documented limitations**. It is a backward-compatible source release; it does not migrate or redeploy the private owner runtime. The historical V1 recommendation and evidence remain in [qualification](../history/v1/qualification.md), and V1.1-specific evidence remains in the [V1.1 release record](../history/v1.1/V1.1-RELEASE-COMPLETION.md).

- Host operations target macOS; MLX requires Apple Silicon. GitHub CI validates portable offline contracts on Ubuntu, not the complete host runtime.
- Fresh source-only build and host-runtime installation use package caches/downloads. MLX qualification reused existing cached weights; no new multi-GB model download was performed.
- Calendar/Gmail reads, local generation, synthetic file/Markdown actions, MCP transports, owner-run Messages reads and real Browser Guard checks passed their recorded qualifications. Broad personal-answer factual accuracy was not independently audited. The small local model selected an unavailable sandbox browser in one chat test, so reliable autonomous browser-target selection is not established.
- Work Mode remains one exact replacement in one observed existing UTF-8 regular file. It does not expose file creation, deletion, batching, fuzzy matching, AST repair, whole-file fallback, helper-model correction or host-authored replacement code. Supported host writers are serialized; arbitrary noncooperating owner processes remain outside that boundary.
- Agent management is deliberately not autonomous authority. Management roles cannot set `Ready for Agent`, add `symphony`, edit source, merge or move work to Done. Implementation concurrency is one, both execution gates are owner-set, independent review is advisory, and every implementation stops at Human Review.
- The Symphony Git path was qualified with a controlled documentation-only issue-to-PR smoke. That proves the bounded lifecycle and control plane, not universal coding reliability. The separately installed Symphony reference and owner-controlled credentials remain outside this repository.
- Codex desktop schedules require the Mac and desktop app to be available. Role state, locks, logs, Linear metadata, credentials, Symphony workspaces, operation receipts and incidents remain external private runtime data.
- Splunk Observability coverage is limited to manual authenticated-gateway traces and a bounded custom metric set. Export is optional and fail-open. No prompts, responses, credentials or arbitrary private content are telemetry fields, and no telemetry affects authority or completion.
- Runpod/vLLM/GPU/host monitoring, collectors, dashboards, detectors, profiling, RUM, automatic content-bearing instrumentation, agent observability and an Observability Steward are absent. One historical Splunk Enterprise JSONL batch remains merged because it was indexed before the sourcetype was corrected; future ingestion uses the documented no-line-merge JSON settings.
- The bounded signed-worker GPU lifecycle and isolated launchd restart/sweep passed. Actual logout/reboot, production cutover and an interactive WebUI GPU conversation were not tested. Simultaneous Mac/network/provider outages cannot guarantee cleanup; preserve cleanup supervision and persistent volumes when ownership is uncertain.
- Vitest 3.2.7 retains a development-only moderate advisory. Its vulnerable dev-server path is unused; no upstream same-major patch exists. Apache-2.0 covers Sanctum source, but the complete external dependency stack is not uniformly Apache-licensed.
- Existing gate jobs and approvals are process-local. Migration requires fresh sessions; history and File Steward undo records have no general importer.
- In the final retained Messages test, the model returned a separate JSON `draft` field but omitted the requested literal DRAFT marker inside it. The strict formatting assertion failed and is retained; source quoting and write rejection passed. Treat generated prose as a draft requiring review.
