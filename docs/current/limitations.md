# Current release and V1.3 integration limitations

Sanctum V1.3.0 extends the immutable V1.2.0 source line with documented
limitations. Source publication does not migrate or redeploy the private owner
runtime. The historical V1 recommendation and evidence remain in
[qualification](../history/v1/qualification.md), and V1.1-specific evidence
remains in the [V1.1 release record](../history/v1.1/V1.1-RELEASE-COMPLETION.md).

- Host operations target macOS; MLX requires Apple Silicon. GitHub CI validates portable offline contracts on Ubuntu, not the complete host runtime.
- Fresh source-only build and host-runtime installation use package caches/downloads. MLX qualification reused existing cached weights; no new multi-GB model download was performed.
- Calendar/Gmail reads, local generation, synthetic file/Markdown actions, MCP transports, owner-run Messages reads and real Browser Guard checks passed their recorded qualifications. Broad personal-answer factual accuracy was not independently audited. The small local model selected an unavailable sandbox browser in one chat test, so reliable autonomous browser-target selection is not established.
- V1.3 Work Mode supports one exact replacement in an observed UTF-8 file, bounded text-file create/delete/move operations, and one exact preflighted multi-file unified text patch with rollback on partial failure. It still does not expose arbitrary host paths, symlink traversal, binary/vendor/generated edits, fuzzy matching, AST repair, generic shell arguments, live host mounts, Docker-socket access or worker credentials. Create/move refuse an existing destination; delete/move require an observed source. Supported host writers are serialized, while arbitrary noncooperating owner processes remain outside that boundary.
- Work Mode is not enabled by fresh core setup. Its stopped-gateway amendment requires an accepted deployment with permanent private-80B retirement, both managed releases offline, zero leases/uncertain ownership, a loaded independent janitor and a healthy local Docker engine.
- One owner-gated small Qwen Work Mode implementation reached a validated pull request and Human Review in a synthetic non-Sanctum repository. Two live Qwen Code MoodLog Work Mode attempts failed before host import. A later unassisted isolated Qwen Code proof passed its tests and browser checks, but it did not pass through Work Mode's import, evaluator, reviewer or Human Review. Broad Qwen coding quality and a completed live Qwen Code MoodLog Work Mode task remain unqualified.
- Agent management is deliberately not autonomous authority. Management roles cannot set `Ready for Agent`, add `symphony`, edit source, merge or move work to Done. V1.3 permits up to five implementation workers in one Symphony service; both execution gates are owner-set, independent review is advisory, and every implementation stops at Human Review.
- The Symphony Git path was qualified with a controlled documentation-only issue-to-PR smoke. That proves the bounded lifecycle and control plane, not universal coding reliability. The separately installed Symphony reference and owner-controlled credentials remain outside this repository.
- Codex desktop schedules require the Mac and desktop app to be available. Role state, locks, logs, Linear metadata, credentials, Symphony workspaces, operation receipts and incidents remain external private runtime data.
- Gateway Splunk Observability coverage remains manual authenticated-gateway traces and a bounded custom metric set. A separate owner-enabled local Codex development lane sends native traces through a private loopback collector to Splunk Agent Observability; TTE-98, TTE-99 and TTE-100 qualified transport, content-free token telemetry, and Symphony attempt/outcome correlation. Both paths are optional, fail-open and irrelevant to authority or completion. The normalized native LLM model display remains empty because its model attribute is on an ancestor request span; no hard-coded or requested-model substitute is used.
- Runpod/vLLM/GPU/host monitoring, broader collectors, dashboards, detectors, profiling, RUM, automatic content-bearing instrumentation, product Agent Observability and an Observability Steward remain absent. One historical Splunk Enterprise JSONL batch remains merged because it was indexed before the sourcetype was corrected; future ingestion uses the documented no-line-merge JSON settings.
- The bounded signed-worker GPU lifecycle and isolated launchd restart/sweep passed. Actual logout/reboot, production cutover and an interactive WebUI GPU conversation were not tested. Simultaneous Mac/network/provider outages cannot guarantee cleanup; preserve cleanup supervision and persistent volumes when ownership is uncertain.
- Vitest 3.2.7 retains a development-only moderate advisory. Its vulnerable dev-server path is unused; no upstream same-major patch exists. Apache-2.0 covers Sanctum source, but the complete external dependency stack is not uniformly Apache-licensed.
- The inherited V1.3 dependency graph has additional production-path npm advisories, including high-severity transitive `brace-expansion` and `undici` entries. Reachability has not been ruled out; no runtime pin is changed by release completion. See the [dependency review](../development/dependency-review.md) for the bounded audit result and required pin-review boundary.
- Existing gate jobs and approvals are process-local. Migration requires fresh sessions; history and File Steward undo records have no general importer.
- In the final retained Messages test, the model returned a separate JSON `draft` field but omitted the requested literal DRAFT marker inside it. The strict formatting assertion failed and is retained; source quoting and write rejection passed. Treat generated prose as a draft requiring review.
