# Roadmap

Immediate release work: close fresh-host and optional-integration setup gaps, validate service-supervision installation on a fresh host, validate saved-chat UI and Calendar natural-language semantics, retain the reviewed dependency exception, close live qualification and complete publication acceptance.

After packaged V1: use the system for real work and collect content-free evidence of bad routes, escalation cost, cold starts, approval friction, context exhaustion and source mistakes. Improve retrieval only when concrete failures justify it.

Future possibilities include a higher-memory local visual model, a home inference server, better durable jobs, targeted retrieval and a separately designed remote-planner/local-executor protocol. AWS remains an optional learning track.

Communication/calendar writes, batch filesystem authority and new MCP integrations require separate narrow designs and explicit approval semantics. Generic shell, remote direct Mac control, automatic privacy declassification, broad deletion and standing approval are not packaging TODOs.

## Release blockers before V1

Improve local-model browser-target selection and broaden factual-quality evaluation after V1. Bounded candidate Messages broker acceptance is complete; a general factual-accuracy guarantee is not a V1 claim. Janitor execution, the bounded private GPU lifecycle, interactive WebUI arithmetic and native browser authority checks now pass. These are release qualification work, not new capabilities. After V1, evaluate a supported Vitest major deliberately rather than forcing incompatible mocker overrides. A full history/undo migration importer and all-container deployment remain future work.
