# Roadmap

Sanctum V1.2.0 is the preceding immutable release. The reviewed V1.3 source
line accumulates on `v1.3-dev`; release completion, promotion to `main`, and
immutable V1.3.0 publication each retain a separate owner gate. Private-runtime
migration requires its own authorization.

Operate the bounded agent-management system against the `Sanctum V1.3` Linear project at an owner-approved cap of five implementation workers in one Symphony service and collect content-free evidence from actual failures. A stop callback may recommend one host-bounded continuation, but cannot change execution gates, code, or merge state. Preserve owner-only `Ready for Agent` plus `symphony` authorization, Human Review, merge and Done transitions. Project membership or the `v1.3.0` milestone never authorizes execution. Any broader implementation concurrency, new management authority or automated merge path requires a separate reviewed design.

Continue the metadata-only Core event path, the gateway-only Splunk APM/custom-
metric slice, and the separately qualified local Codex development Agent
Observability lane. Its private loopback collector and Symphony correlation
do not qualify product agent monitoring. Runpod/vLLM/GPU/host monitoring,
broader collectors, dashboards, detectors, profiling, RUM, product Agent
Observability and an Observability Steward remain deferred. The normalized
Codex LLM model field remains empty until a safe trace-aware mapping is
reviewed. Observability may not become an authority, routing, egress,
capability, evaluator, verifier or completion input.

Product work remains evidence-driven: improve local-model browser-target selection, factual-quality evaluation, retrieval, durable jobs, approval ergonomics and cold-start behavior only when concrete failures justify a bounded project. Evaluate a supported Vitest major deliberately rather than forcing an incompatible override.

Communication/calendar writes, batch filesystem authority, new MCP integrations, higher-memory local visual models, a home inference server and a separately designed remote-planner/local-executor protocol remain future possibilities. Generic shell, remote direct Mac control, automatic privacy declassification, broad deletion and standing approval are not roadmap shortcuts. A full history/undo migration importer, unattended production cutover and an all-container deployment also remain unsupported.
