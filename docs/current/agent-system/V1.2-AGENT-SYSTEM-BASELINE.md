# V1.2 agent-management baseline

Date: 2026-09-18 (America/Los_Angeles). This is a source-only baseline and
architecture decision. It does not amend the private VinceAI runtime, enable a
scheduled task, write Linear, start Symphony, or authorize implementation work.

## Observed baseline

- `v1.2-dev` exists locally and on the canonical remote. This project branches
  from its latest merged commit, never from an unmerged sibling.
- GitHub CLI and Codex are authenticated. The existing `Offline contracts`
  workflow is green on `v1.2-dev`.
- Codex CLI 0.155.1 exposes the v2 app-server protocol. Its live model catalog
  contains `gpt-5.6-sol`, `gpt-5.6-terra`, and `gpt-5.6-luna` with every
  reasoning effort selected by this project.
- `WORKFLOW.md` already requires the `symphony` label, polls only active
  implementation states, creates issue workspaces from `v1.2-dev`, opens PRs
  against `v1.2-dev`, and stops at `Human Review` without merging.
- The separately installed Symphony reference is the upstream engineering
  preview. It provides isolated workspaces, tracker polling, host-side
  `linear_graphql`, token totals, stall detection, retries and structured logs.
- The existing dependency environment was inspected before reuse. `make deps`,
  `make build`, `make test`, and `make audit` pass before this project.
- The private owner runtime remains outside Git and the legacy repository
  remains read-only historical evidence.

## Correct but incomplete

The existing Symphony workflow is a sound implementation handoff skeleton. It
does not implement Repo Steward, Product Scout, Triage, independent PR review,
central role/model configuration, scheduling, shadow evidence, or a
Sanctum-owned budget governor.

The current CI validates the existing offline contracts but has no focused
agent-system test job. No current source command provides per-role locks,
stale-lock recovery, dry-run/shadow enforcement, persisted incremental cursors,
structured agent run records, or explicit external-call limits.

## Unsafe or fragile observations

- Symphony `max_turns` bounds only one worker lifetime. Normal exits schedule
  continuation retries, and failure retries are not capped by a total-attempt
  limit.
- Symphony `turn_timeout_ms` is a silence interval, not a total turn duration.
  `stall_timeout_ms` is also activity-based. Neither prevents an active but
  runaway session.
- The existing workflow does not select a model centrally or fail closed when
  a requested model is unavailable.
- The copied upstream landing workflow can merge PRs and is therefore outside
  Sanctum's authority model.
- Live Linear metadata could not be inspected from the Phase 0 shell because
  no raw token is exported and `linear_graphql` is intentionally available only
  inside an authenticated Symphony session. Source implementation can proceed;
  live writes and smoke acceptance remain disabled until that access is
  available.
- `npm ci` reports two moderate dependency advisories. This project will not
  take unrelated dependency upgrades without a scoped finding and review.

## Phase plan

1. Add the shared fail-closed runner, central configuration, locks, budgets,
   structured logs and integration boundaries.
2. Add Repo Steward with incremental repository evidence and shadow output.
3. Add Product Scout with bounded source intake and shadow output.
4. Add Triage with deterministic authority filters and fixture acceptance.
5. Add a Symphony supervisor with hard total-runtime, token, turn and retry
   budgets plus proportional validation profiles.
6. Add a separate-context, read-only PR Reviewer.
7. Add scheduling instructions, CI, operator documentation, final offline
   validation and live-smoke prerequisites.

Every live mutation remains off by default. Passing offline tests proves
software boundaries, not authenticated Linear/GitHub behavior.
