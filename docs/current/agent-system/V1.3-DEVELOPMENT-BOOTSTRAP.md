# Sanctum V1.3 development bootstrap

Date: 2026-09-20. V1.3 development starts from immutable release `v1.2.0`,
commit `3e27dfafba75058e85f24db4a235ce63e71846fd`. The `v1.3-dev` integration
branch was created from that exact commit. New work uses a dedicated
`v1.3/project-*` branch based on the latest reviewed `origin/v1.3-dev`, returns
by pull request, and is never merged automatically.

The live project exposes the previously qualified workflow states, including
`Triage`, `Backlog`, `Watch`, `Ready for Agent`, `In Progress`, `Human Review`,
`Rework`, `Merging`, `Done`, `Duplicate`, and `Canceled`. It also exposes the
`symphony` execution label, the `source` group and its management-source
labels, normal classification labels, and the Engineering Finding, Product
Discovery, and Agent Quality Finding templates. The project contains no issues
at bootstrap time.

Project membership, a milestone, a source label, or management-agent output is
not implementation authority. Symphony eligibility remains exactly the
owner-set `Ready for Agent` state plus the owner-set `symphony` label.
Management roles may observe and propose but cannot set either gate, edit
source, merge, or move work to Done. An implementation worker uses one
workspace at a time, targets `v1.3-dev`, and stops at `Human Review`.

## Source bindings

The reviewed bootstrap updates the Linear project slug, integration branch,
private-prefix default, Symphony workflow, Git broker, lifecycle validation,
synthetic fixtures, CI push branch, Dependabot targets, tests and current
operator documentation together. Package metadata remains `1.2.0` until a
separate V1.3 release-completion project; opening a development line is not a
release version change.

The private prefix changes to `~/.sanctum/agents-v1.3` so V1.2 state and
receipts remain intact. Source review does not create that prefix, copy tokens,
install schedules, or amend the running private system. Before enabling V1.3
management or implementation, capture the live Linear metadata into the new
private prefix, run the metadata/config/model/schedule checks, perform fresh
shadow runs, and inspect the private evidence. The first implementation must
remain a tiny owner-authorized smoke and must stop at Human Review.

## Rollback

Before merge, close or revise the bootstrap pull request. After merge, revert
it through a reviewed pull request to `v1.3-dev`; do not move the immutable
`v1.2.0` tag or rewrite `main`, `v1.2-dev`, or `v1.3-dev`. Pause any V1.3
automations before reverting an activated private configuration. Preserve the
external V1.3 prefix and receipts until ownership and in-flight work are
reconciled.
