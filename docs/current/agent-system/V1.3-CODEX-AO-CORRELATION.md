# Codex Agent Observability correlation (V1.3 development)

This is observational evidence for the local Symphony/Codex development lane.
It never authorizes execution, changes a worker decision, grants egress, or
determines whether an issue is complete. The source-controlled Codex command
still sends only traces to the loopback collector at
`http://127.0.0.1:4318/v1/traces`; prompt logging, OTel logs, and OTel
metrics remain disabled. Collector configuration and Splunk credentials stay
in the private owner prefix.

## Correlation architecture

The host supervisor reads Symphony's structured `/api/v1/state` snapshot. On
the first observation of a running attempt it emits a small independent OTLP
span to the existing local collector and writes the same safe fields to a
private mode-0600 journal. The attempt ID is a stable hash of the supervisor
run ID, Linear issue UUID, and Symphony attempt start timestamp. A later
session-observed span binds that attempt to Codex's thread and turn IDs from
Symphony's structured session ID. The spans are joined by those identifiers;
they do not pretend to be parents of native Codex spans.

The supervisor also keeps a short-lived, exact-workspace attempt binding in
the external private prefix. The host Git broker reads it only as optional
evidence when it records a commit or PR receipt. A missing or stale binding
leaves Git behavior unchanged and does not attribute the artifact to an
attempt. The broker does not consult AO to decide whether to commit, push, or
create a PR.

`symphony-ao-reconcile --issue TTE-N` reads confirmed host receipts and
read-only Linear/GitHub state after those facts are available. It prints safe
fields by default. `--emit` sends one issue-level outcome span to the local
collector. A PR head is attributed to an attempt only when its confirmed
GitHub head SHA exactly matches one applied PR receipt carrying a fresh
attempt binding. CI is reported only after all returned checks finish.
Linear state and GitHub PR state are reported independently; a disappearing
worker is never called a successful run.

| Timing | Fields emitted when observed |
| --- | --- |
| Attempt start | Linear identifier and UUID, Symphony run and attempt IDs, worker class, configured model, reasoning effort, start time |
| Session available | Codex thread and turn IDs, joined to the observed attempt |
| Retry/stop | Explicit Symphony retry number, blocked state, or supervisor stop reason; unknown final outcomes remain absent |
| Reconciliation | Linear state, validated PR number/branch/head, confirmed attempt binding, completed CI result, count and latest result of host validation receipts |

Issue, run, attempt, thread, commit, and PR identifiers are **trace
attributes**, never metric dimensions. Workspace paths, prompts, responses,
reasoning content, files, patches, tool arguments/outputs, command bodies,
credentials, and arbitrary error text are not exported by this bridge. The
private journal contains the same safe allowlist. AO delivery uses a 200 ms
loopback timeout and is fail-open; no worker or supervisor outcome depends on
the collector.

## Model identity and token accounting

The supervisor's model field is the **configured/requested** model from the
reviewed workflow. It is selected dynamically for the worker class, so no
single model name is baked into correlation code. It is not a claim that every
native LLM call used that model. The current private collector normalization
looks for a `model` **span** attribute, while Codex's telemetry documentation
describes model as event metadata. The exact native resource/span key in the
qualified TTE-98 trace still needs a read-only check. Until that check, the
bridge does not rewrite native LLM spans or fill their blank AO model field
from the requested model. Once the raw key is proven, review a narrow private
collector amendment that projects the native model dynamically; keep the
private collector file outside Git. Do not use a constant `gpt-5.6-sol` value.

Symphony's `input_tokens`, `output_tokens`, and `total_tokens` are cumulative
context counters in the state API. The bridge names them
`context_*_tokens` on an attempt-closing span, never ticket cost. For a
ticket-level usage analysis, deduplicate native response-completion model
spans by their span identity and sum per-call **non-cached input** (`input -
cached input`), cached input, and output separately. Reasoning output is a
subset of output; report it separately rather than adding it again. Count
distinct model-call spans and distinct observed attempt IDs. Missing usage or
model fields stay unknown. Dollar cost requires a reviewed model-specific
price schedule and billing semantics; this bridge does not infer it or change
Token Meter.

## Offline and live qualification

The deterministic tests use synthetic Symphony snapshots, Git receipts, and
provider results. They cover stable issue/attempt/session identity, explicit
retry numbers, absent facts, exact-workspace receipt binding, OTLP JSON shape,
and unavailable collector behavior. The TTE-98 `WORKFLOW.md` OTel guard must
continue passing. This change does not dispatch a Linear issue or update the
private collector.

After the PR and runtime source pin are reviewed, one small owner-gated
Symphony ticket should produce:

1. `sanctum.symphony.attempt_observed` with the issue ID and attempt ID.
2. `sanctum.symphony.codex_session_observed` with a thread ID matching the
   native Codex conversation identifier in AO.
3. A host PR receipt with the same attempt ID, followed by a read-only
   `symphony-ao-reconcile --issue TTE-N` preview.
4. Once CI has completed, an owner-invoked `--emit` reconciliation whose AO
   outcome span reports the actual Linear, PR, validation, and CI states.
5. Native LLM spans still show no prompt/response content. Inspect only their
   model **attribute names and location** to decide the private normalization
   amendment; do not repeat transport canaries.

This procedure is a later owner-authorized qualification. The new source must
be accepted and the existing supervised service restarted before it can emit
these spans. A merged PR alone does not change the running service.

Official Codex telemetry settings and event metadata are documented in the
[Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference)
and [advanced configuration guide](https://learn.chatgpt.com/docs/config-file/config-advanced).
The [OTLP specification](https://github.com/open-telemetry/opentelemetry-proto/blob/main/docs/specification.md)
defines the JSON trace payload sent to the local collector.
