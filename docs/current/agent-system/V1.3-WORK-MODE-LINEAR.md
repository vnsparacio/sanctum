# V1.3 Work Mode Linear evidence boundary

The first Work Mode Linear slice is deliberately smaller than the full
implementation lifecycle. A host-selected `WorkIssueScope` binds one Linear
internal issue ID, public identifier, project ID, and GitHub repository before
any operation is available. Provider responses must match all three Linear
identities; issue text cannot redirect the binding.

`WorkLinearOperations` exposes scoped evidence operations plus a host-bound
implementation lifecycle. It can fetch the scoped issue, upsert the single
comment whose first line is `## Codex Workpad`, attach the one pull request
whose HTTPS GitHub URL belongs to the scoped repository, consume the exact
owner-set execution gate to enter `In Progress`, and hand an active attempt to
`Human Review`.
The Workpad carries plan, checkpoint, blocker, and validation prose as data.
It does not grant authority.

Each mutation first reads provider state and reads it again after the write.
Exact replay therefore returns the existing comment or attachment. A timeout
after a possibly successful mutation is reconciled by one scoped read; an
unobservable result fails as unknown instead of blindly creating another
artifact. Multiple active Workpads, duplicate PR attachments, an existing
different task PR, truncated comment pagination, and identity drift all fail
closed.

Lifecycle state IDs and owner identities come from a separate immutable
`WorkLifecycleScope`; they are never accepted from model output or issue text.
The only representable state writes are `Ready for Agent` to `In Progress` and
`In Progress`/`Rework` to `Human Review`. Exact-target replay is read-only and
an uncertain write is reconciled once from provider state. There is no label
mutation, issue creation, `Done` transition, merge, or arbitrary GraphQL
operation, so the worker can consume but cannot manufacture its execution
gate.

`Human Review` remains a hard wait. Feedback intake succeeds only while the
owner has explicitly moved the fixed issue to `Rework`, a single existing
Workpad is present, and trusted Git control-plane facts identify the same open,
unmerged issue branch and attached PR. The Workpad's `### Review checkpoint`
is parsed by provider-stable ID on every intake, so retries omit already
handled feedback. Linear and GitHub feedback is selected only when its provider
identity exactly matches the host-bound owner identity; Workpad, bot,
integration, and unknown-author comments cannot become owner authority.
