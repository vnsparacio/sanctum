# V1.2 Symphony Git control plane

## Root cause

Codex `workspace-write` permits ordinary workspace edits but recursively
protects `.git`, including a `.git` pointer and its resolved Git directory.
TTE-9 therefore could edit source but could not fetch or create
`.git/index.lock`. This was an architecture mismatch, not a Unix ownership
failure.

The installed Codex 0.155.1 reproduction created `ordinary.txt` and denied a
write to `.git/FETCH_HEAD` with `operation_not_permitted`. The worker selects
the `sanctum-workspace` permission profile, which extends Codex's built-in
`:workspace` profile and enables network access; neither `danger-full-access`
nor `externalSandbox` is used. The reviewed Symphony adapter must support
`codex.turn_permission_profile` and serialize it as `turn/start.permissions`
without also sending `sandboxPolicy`.

## Selected architecture

Symphony's host lifecycle hooks clone the fixed canonical remote and invoke a
source-manifest-verified Sanctum broker before the Codex turn. The broker
fetches only `origin/v1.3-dev`, creates `symphony/<issue>` only from that exact
accepted ref, or validates the already-current issue branch. Codex then edits
ordinary files inside its restricted workspace.

The same broker is exposed as a local stdio MCP server with four Git tools and
one separate GitHub handoff tool:

- `git_workspace_status`: read the branch, HEAD, and changed paths;
- `git_commit_issue_changes`: stage explicit relative paths and commit on the
  deterministic branch;
- `git_push_issue_branch`: normally push that branch to `origin`;
- `git_reconcile_operation`: reconcile a pending commit or push receipt without
  replay;
- `github_ensure_issue_pull_request`: update or create the one open PR from the
  deterministic issue branch to `v1.3-dev` without merge authority.

No operation accepts a remote, base, branch, refspec, force flag, deletion, or
raw Git arguments from the model.

## Deterministic validation

Before mutation the broker requires a real, non-symlink direct child of the
configured external Symphony workspace root. Its basename must be a supported
issue identifier. `.git` must be an in-place directory whose top-level,
absolute Git dir, and common Git dir all resolve to that workspace. The only
remote must be `origin`, and both fetch and push URLs must equal
`https://github.com/vnsparacio/sanctum.git`. Unexpected local Git config,
alternate Git dirs, pointer files, workspace symlinks, protected/private commit
paths, and submodules fail closed.

PR lookup binds the base, branch, canonical head repository/owner, and exact
local/pushed head OID, so a fork using the same branch name cannot be edited or
accepted as the issue handoff.

The host lease binds the resolved workspace/root/Git-dir paths, workspace and
Git-directory filesystem device/inode identities, issue, base, remote, and
deterministic branch. An existing lease must match before fetch or any other
write; it is never silently replaced. The lease and operation receipts are
mode-restricted state outside Git.

## Credentials and repository trust

The broker uses `/usr/bin/git`, disables repository hooks, ignores global and
system Git configuration, and supplies a fixed, path-validated GitHub CLI only
for bounded remote inspection, push, and PR handoff. Its authentication config
is an owner-created private directory outside both source and issue workspaces;
the worker sandbox cannot read it, and raw GitHub authentication is not placed
in the worker environment. The broker passes an allowlisted subprocess
environment and never returns credential values or environment dumps. The
source executed as the broker is the canonical source-manifest-verified copy,
not mutable code in the issue checkout.

## Failure and replay semantics

Commit writes a pending private receipt containing the pre-HEAD and expected
tree before invoking Git. Push writes a pending receipt containing local HEAD
and prior remote branch state. A timeout or lost result is reconciled against
the actual commit parent/tree or remote branch head. Matching state becomes
`reconciled`; divergent or unavailable state remains `UNKNOWN` and requires
operator review. The broker never force-pushes and never automatically replays
an unknown operation. Before a commit receipt exists, any staging failure
restores the index to `HEAD`; an unconfirmable restore also becomes `UNKNOWN`
instead of leaving a silently wedged index.

An immutable environment/control-plane blocker is recorded once and requests
operator input. Symphony places the issue in its blocked runtime state, which
the Sanctum supervisor treats as terminal for that invocation instead of
scheduling continuations or retries.

## Rejected alternatives

- `danger-full-access` and bypass flags grant unrelated host filesystem
  authority and are prohibited.
- `externalSandbox` was rejected because Sanctum does not currently establish
  a separately reviewed process sandbox with the required filesystem,
  credential, and network containment.
- Lifecycle hooks alone cannot complete commit/push after source edits, and the
  installed hooks expose only the workspace `cwd`, not issue template values.
- Modifying Symphony's tracker-specific dynamic-tool adapter would couple Git
  authority to external Symphony source. The local MCP surface avoids that
  modification while retaining host execution and a narrow schema.
