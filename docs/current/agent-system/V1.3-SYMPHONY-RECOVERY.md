# Symphony exit recovery and Gmail alerting

`symphony-run` runs one standard or deep service with at most five concurrent
issue workers. Each state API request retains a two-second timeout. Startup has
a bounded 120-second grace because Symphony cleans terminal workspaces before
binding the API; after the first successful snapshot, outages retain the
30-second limit. The recovery advisor runs only after that service exits. No
scheduled Codex poller or public webhook is required. A hard Mac shutdown
cannot execute a local callback; review the existing private incident after
power is restored.

On a single issue's token, turn or wall-clock stop, the host validates the
incident, original ledger, prior turn progress, deterministic issue workspace
and branch, and absence of unresolved Git operations. It then asks a bounded
read-only `triage` Codex run to choose `CONTINUE_ONCE` or `NEEDS_OWNER` using
only issue ID and numeric metadata. The host alone grants up to 30 minutes,
six turns and 250,000 tokens, cumulatively in the same ledger epoch. A second
stop is reported, never automatically continued. Other stop classes are
reported without an advisor call. The shared lock and state port mean that
standard and deep services remain mutually exclusive even at five workers.
This does not change Symphony's Linear execution gate or the owner-only
Human Review, PR merge and Done transitions.

## Local Gmail enrollment

Use the V1.3 private runtime, not the retained V1.2 prefix. Create a mode-0600
`$SANCTUM_AGENT_PREFIX/config/symphony-notifications.json` file containing
`{"sender":"YOUR_GMAIL_ADDRESS","recipient":"YOUR_NOTIFICATION_ADDRESS"}`.
For this owner, the intended recipient is the provided Symphony plus-address;
keep the binding outside Git. Save the Gmail app password under the macOS
Keychain generic-password service `sanctum-symphony-gmail-smtp`, with the
sender address as its account name. For example, run this locally in Terminal
and enter the app password only at its prompt:

```sh
security add-generic-password -U -s sanctum-symphony-gmail-smtp \
  -a YOUR_GMAIL_ADDRESS -w
```

Google requires 2-Step Verification for app passwords. Never paste an app
password in chat, put it in an environment variable, or commit it. Alerts use
`smtp.gmail.com:587` with STARTTLS, a short timeout, and a sanitized message
containing only issue ID, stop category and private incident basename. Every
attempt gets a private receipt under `state/symphony-recovery/`; ambiguous
sends are not retried automatically. If SMTP enrollment or network access is
missing, the receipt says `failed` and the CLI prints its path. No email is
sent for a successful normal worker completion while the service keeps running.

After the source PR is merged, run `make deps`, `make build`, `make test`,
`make audit`, then standard/deep `symphony-preflight` in the reviewed source
checkout. Keep the owner-only Linear gate. Start exactly one service through
`symphony-run` (pass `--worker-class deep` only for a deep-routed issue).
Use a tiny authorized issue for first live qualification; tests are synthetic
and do not prove live SMTP delivery or successful issue completion. The
legacy `symphony-resume` command remains an explicit owner decision and starts
a new budget epoch; it clears any automatic extension for that issue.
