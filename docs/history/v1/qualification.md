## Scope and retained failures

The original disk-full installation and launchd xpcproxy failures remain in private evidence. With approximately 39 GiB available, the janitor executed without weakening OS protections. The GPU first answer, including allocation/warmup, took 429.49 seconds; the reused second answer took 5.73 seconds. Provider listings confirmed cleanup before the temporary janitor was unloaded. The rate is a provider preflight observation, not a final billing invoice.

Calendar and Gmail source payloads were processed in memory and sent only to the separate local MLX model. Only sanitized acceptance metadata was retained. No email or text was sent, no personal-source write was attempted, and no personal draft was saved to publication artifacts. The Messages outer wrapper prefetches two extra records, so it was not used for the three-record test. The first exact participant/chat attempt through the installed CLI failed on OS privacy permission. The owner subsequently ran the prepared helper in an already authorized Terminal: at most three matching messages were read, a local summary and labelled unsent draft were produced, and no source content was retained. It verified all four HTTP mutation methods were denied, send was unavailable, and a supporting quote in the local answer exactly matched the source. No personal output was retained. Calendar's underlying all-calendar query can return more than the per-calendar maximum; the real broker's total output cap of twenty was separately verified.

## Interactive WebUI continuation

Open WebUI 0.11.1 adds implicit built-in tools when a browser session is present. Direct HTTP tests lacked that session field and missed the issue. The gate filter now sets legacy function-calling mode for this gate request before WebUI middleware can inject those tools. Explicit uploads, tool requests and feature flags remain rejected. The new regression passed in both full 151-test runs and the fresh source-only build.

Two explicitly approved prompt-only hosted audits were used for arithmetic and browser navigation, adding $0.015442 in adapter accounting. The temporary single-provider profile was removed afterward. Arithmetic completed correctly on local 4B. The browser prompt selected `target="sandbox"`, which is unavailable in this host-native setup; the model reported a backend failure and did not retry correctly. A separate native-runtime test with the configured isolated `openclaw` profile and `target="host"` passed navigation and approval-bound interaction. This establishes the packaged browser boundary, not reliable autonomous browser-target selection by the small model. No third hosted audit was run.

Two browser harness attempts failed to locate the heading because the harness initially read metadata instead of content, then omitted the heading level from its reference matcher. Both attempts stopped their test browser; both failures were retained before the corrected live test passed.

The first owner-helper launcher update accidentally retained its old target and therefore repeated the native check. A distinctly named corrected launcher was verified before the final candidate broker run. This harness mistake is retained in the private worklog and did not alter source permissions or the three-record bound.

The functional unsent-draft check is supported by the separate structured field and absence of send authority; the missing literal label is a recorded small-model instruction-following limitation, not a claimed full pass of the original assertion. No additional personal read was made to obtain a cleaner result.
