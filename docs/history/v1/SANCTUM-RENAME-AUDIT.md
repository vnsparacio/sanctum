# Sanctum rename audit

Prepared before source edits. Sanctum is the public framework; VinceAI names the original personal/reference deployment. The canonical project report preserves historical research and provenance. Current behavior is governed by the qualified candidate and its acceptance matrix. No production files are migration targets in this task.

## Decisions

Rename current display text, npm package metadata, new build/test temporary directories, generated janitor labels, new migration example variables and release artifacts. Preserve `VINCEAI_*` runtime environment variables, `vinceai-reliability`/`vinceai-mcp-guard` plugin IDs, `vinceai__*` MCP tool names, MCP profile ID/catalog references, File Steward/privacy scope `vinceai`, GPU model alias/Pod ownership prefix/cache layout, Keychain labels, legacy fallback paths, telemetry/idempotency identities and the legacy phase migration helper. Renaming these would split qualified schemas, persisted approvals/configuration, resource reconciliation or existing credentials. No alias layer or migration is introduced for naming purity. Public display names use Sanctum.

Historical before-schema fixtures and report source filenames remain unchanged. The report's 174-file count and 151-test count describe the pre-rename qualification; current publication counts are recorded separately. Full source history is not imported.

The six newly found Finder `.DS_Store` files are private/generated metadata, already ignored by Git/Docker. Remove them from candidate publication scope and make the existing scanner reject their reintroduction. Private `.local/`, dependencies, compiled outputs and historical task evidence are excluded; their identifiers are not rewritten.
