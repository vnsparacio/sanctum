# Project 3 owner-authorized coding budget amendment

The unseen interval task reached its fixed 16-iteration limit: five reads, nine patch proposals (three applied and six rejected before execution), and two failing tests. The final Qwen-authored patch passes all five unchanged tests in subsequent local diagnosis, but the installed task stopped before requesting a final passing test, evaluation, or review. It remains an ITERATION_LIMIT result, not a clean Stage A success. No schema failure, uncertain execution, authority denial or egress denial was observed.

The owner then explicitly expanded time/spend authorization: “dont worry about time; we have money. just go for it.” The same allocation was transferred from the original no-inference diagnostic wait to a fresh independently supervised lease. No replacement allocation was created. The original private ledger and patch were preserved. A separate verification caller attempted one test-only proposal with incomplete observation history; it received a valid ESCALATION. This did not resume or relabel the original task and is not production acceptance evidence. No qualification ran.

The resulting plan is to raise the separately registered unseen task's host budget to 32 iterations, 32 model calls and 200,000 total tokens, then execute the original unchanged baseline and goal again on the same GPU. This is a new owner-authorized run after an explicit budget/source amendment, not a claim that the original run passed. Per-response generation limits, model/revision/serving pins, prompts, schemas, sandbox, authority, egress, tests, evaluator, reviewer, task time, inference-time and cost limits are unchanged. Existing canonical and qualification profiles remain unchanged.

Regression tests cover preservation, rollback, excessive budgets, wrong ownership, protected profiles, missing supervision and active workers.
