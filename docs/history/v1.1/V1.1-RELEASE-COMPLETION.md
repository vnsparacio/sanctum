# Sanctum V1.1.0 release completion

Date: 2026-09-17. This document records the completed V1.1 minor-release candidate. It is a source and evidence handoff for review and tagging; it does not move stable `main`, create a tag, publish a GitHub release, migrate production, or change a private owner runtime.

## Scope

V1.1 integrates four accepted projects on `v1.1-dev`:

- Project 0: isolated owner baseline and cleanup discipline.
- Project 1: versioned, Mac-owned capability, authority, egress and result-envelope contracts.
- Project 2: bounded Source-First evidence retrieval and verified citations.
- Project 3: privately hosted Qwen Work Mode, isolated candidate workspaces, protected-original-test proof, evaluator/reviewer gates, and exact structured editing.

The root package version and lockfile are `1.1.0`. Existing dependency, model, serving and sampling pins are unchanged. The earlier `v1.0.0` tag remains immutable.

## Acceptance evidence

The final source verification passed `make deps`, `make build`, `make test`, and `make audit`. The packaged suite contains 510 tests with zero failures or skips; the publication audit scanned 318 files with zero issues. Both GitHub Ubuntu checks passed after a portable-fixture regression proved that live amendments still fail closed on non-macOS hosts.

Project 3's independent offline review passed. Its fresh, unseen canary completed with one exact Qwen-authored edit, passing protected original and candidate tests, evaluator and reviewer. The unchanged 11-case qualification then produced nine genuine `COMPLETE` cases, one expected `NEEDS_APPROVAL` stop and one expected `BLOCKED` safety stop. All nine suite edit proposals applied. Across canary and suite, 10 of 10 semantic edit proposals applied with zero fuzzy matches, host-authored source, blind retries, authority/egress failures or unresolved execution uncertainty. The detailed case table, exact design, private-evidence locators and rollback procedure are in [the structured-editing report](project-3/PROJECT-3-STRUCTURED-EDITING.md).

The supervised private run used one cache-only allocation. Cleanup independently confirmed zero Pods, managed allocations, leases, unfinished experiments, task containers and retained run workspace records; persistent volumes were preserved, GPU autostarts stayed disabled and the independent janitor remained loaded. Private evidence, receipts, state and account bindings remain outside this repository.

## Deliberate limits

V1.1 does not claim universal coding reliability, full Linux product parity, an all-container deployment, autonomous owner-level filesystem safety, or a production cutover. Work Mode editing is deliberately one exact replacement in one observed existing UTF-8 regular file. It does not expose file creation, deletion, batching, fuzzy matching, AST repair, whole-file fallback, helper-model correction or host-authored replacement code. Live mismatch recovery was not sampled because no exact match failed; deterministic tests cover the required reread path.

Supported host writers are serialized. Arbitrary noncooperating trusted-owner processes remain outside that boundary, so task workspaces must remain quiescent outside supported host APIs. The known V1 limitations, including the development-only Vitest advisory, remain documented in [limitations](../../current/limitations.md) and [dependency review](../../development/dependency-review.md).

## Release and rollback

This candidate is ready for review into `v1.1-dev`. After merge, the owner may create `v1.1.0` only from the reviewed merge commit using [the release procedure](../../guides/release.md). Do not retag V1.0.0 or force-push history.

For a private Work Mode rollback, stop the gateway, verify no provider ownership or unresolved leases, retain the janitor and persistent volumes, then restore the recorded private amendments in reverse order together with their matching source-linked reliability/schema artifacts. Do not restore only the private gate overlay. See [the structured-editing report](project-3/PROJECT-3-STRUCTURED-EDITING.md) for the precise boundary and private receipt references.
