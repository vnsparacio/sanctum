# Sanctum V1.3.0 release completion

Date: 2026-09-29/30. This record describes the proposed V1.3.0 source
candidate and its owner-controlled review, promotion, tag and publication
gates. Source publication does not install, migrate, amend or repin the
external private owner runtime. The legacy repository, stable `main`, and
existing immutable tags remain untouched by this branch.

## Current limitations and private AO model attribution

The TTE-100 qualified AO trace contains one observed Symphony attempt and 53
distinct completed native `codex.llm.response` spans. The attempt, Codex
conversation/turn, Git branch/commit/PR, validation, CI and Linear states
joined in AO. Per-call token evidence separated cached input, non-cached input,
output and the reasoning subset without summing cumulative context counters
or inferring dollar cost. The LLM content fields were empty; no prompt,
response, hidden reasoning, source, patch, command body, tool arguments or
credentials were observed in the stored trace.

The native model attribute is nonempty on `try_run_sampling_request`, two
parent links above each normalized LLM span. The current private collector
can transform a span's own attributes but cannot safely read an ancestor
attribute through OTTL. Its configuration was **not changed** for this
release. The normalized LLM model field remains blank; the host requested
model is not substituted. A private read-only report can join exact parent IDs
within one trace and show the native model beside completed calls without
changing ingest. An in-memory prototype resolved all 53 qualified calls and
five synthetic exact/missing/foreign-trace/absent-model/existing-model cases;
missing or ambiguous relationships must remain unset. Any ingest-time
enrichment requires a separately reviewed, bounded trace-aware component and
privacy/rollback qualification. This optional display limit does not block the
already-qualified baseline AO integration.

Other retained limits are in [current limitations](../../current/limitations.md).
Full product operation targets macOS on Apple Silicon; Ubuntu CI verifies
portable contract surfaces, not host permissions, MLX, WebUI enrollment,
provider availability or a production cutover. Broad autonomous coding,
full Linux parity, Runpod/vLLM/GPU/host monitoring, automatic private-runtime
migration, and cleanup during simultaneous host/network/provider failure are
not claimed. The development-only Vitest advisory remains documented.

The release metadata change does not alter the locked dependency graph.
An additional `npm audit --omit=dev` review of the accepted V1.3 lockfile on
2026-09-29 reported five production-path advisory entries (two high, three
moderate). The high entries are transitive `brace-expansion@5.0.9` and
`undici@8.10.0`; `undici` is reached through pinned
`openclaw@2026.8.1`. The full audit adds two moderate development-only
Vitest entries, for seven total. These are advisory counts, not proof that
the affected runtime paths are reachable. They must not be described as
vulnerability-free. A dependency/runtime-pin change requires its own source
and private-runtime review; none was silently applied in this release diff.

## Authority, privacy and compatibility

The Mac continues to own authentication, source selection, disclosure,
approval, egress, capability, budgets and resource cleanup. Remote models,
tool output, repository content, web content and telemetry remain evidence,
never authority. Work Mode retains isolated workspaces, protected inputs,
fixed runner commands, exact edit limits, host evaluation, advisory review,
one-use approval and Human Review. Restricted content telemetry remains
private and separate from metadata-only operational and AO signals. No
credentials, owner bindings, model weights, logs, private receipts or live
source contents are included in the release tree.

V1.3.0 adds compatible opt-in capabilities; it does not remove a supported
V1.2 configuration or transfer a policy decision to a model, collector,
provider or management agent. Existing source/runtime pin procedures and
separate stopped-gateway amendments still apply. The release-completion diff
changes version metadata and documentation and corrects two source-archive
qualification defects: the prelive package test now uses the reviewed source
manifest for its inventory, and private amendment receipts record
`source_commit: null` when the verified source has no Git metadata. The
source-manifest digest remains recorded in those receipts; a checkout with a
valid Git root still records its exact 40-character commit. Neither correction
changes runtime policy or installs/amends private state during qualification.

## Promotion, publication and rollback

The release-completion PR targets `v1.3-dev` and stops for owner review.
After its owner merge, a separate PR promotes the unchanged reviewed
`v1.3-dev` tree to `main` and stops for owner review. Only after that owner
merge, exact tree-equivalence and CI checks, and explicit final approval of
the 40-character tag target, artifact SHA-256 and complete notes may the
owner create `v1.3.0` and publish a GitHub release. Neither PR is merged by
the release-preparation agent; tag and publication commands are not run
without that exact approval.

Before publication, source rollback is a reviewed revert with no force-push.
After publication, retain the immutable tag and release and correct defects
in a later version. Private-runtime migration and rollback are independent:
stop the gateway, inspect the matching private rollback transaction and exact
process/resource identities, preserve receipts, cleanup supervision and
persistent volumes, and obtain a separate owner-approved window. Source
publication alone causes no runtime migration or rollback.
