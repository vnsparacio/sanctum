## Accepted scope

V1.2.0 is a large but backward-compatible release. It preserves the governing
invariant: **Reasoning is replaceable. Authority stays on the Mac.**

- Repo Steward, Product Scout and Triage provide bounded management proposals,
  typed Linear payloads, deduplication and capped live writes. They cannot set
  either implementation gate, edit source, merge or move work to Done.
- Symphony executes only issues in `Ready for Agent` with the `symphony` label,
  uses isolated issue workspaces and proportional validation, and stops at
  Human Review. Rework supports bounded fix, plan, clarification and reset
  dispositions while preserving review checkpoints and idempotency.
- The Sanctum supervisor enforces explicit aggregate wall-clock, turn, token,
  retry, stall, output and workload limits. Implementation concurrency remains
  one.
- The bounded Git control plane owns deterministic preparation, transactional
  staging/commit, normal push, reconciliation and one unmerged PR handoff. It
  accepts no arbitrary remote, refspec, force, deletion or raw Git arguments;
  GitHub credentials remain outside the worker context.
- Repository hygiene adds dependency automation, pinned formatting/linting,
  decomposed CI checks, portable path enforcement, broader documentation-link
  checks and explicit source-integrity verification.
- Branding and documentation are organized into current, architectural,
  operator, development and historical surfaces without rewriting historical
  evidence.
- Existing metadata-only operational events continue through the external
  private spool, S3 and Splunk Enterprise. Optional manual traces and bounded
  custom metrics flow directly to Splunk Observability Cloud. Active OTel
  `trace_id` and `span_id` values correlate corresponding `sanctum_ops` events.

## Security and authority boundaries

Linear owns work, findings, decisions and implementation authorization. GitHub
owns branches, commits, PRs, CI and review artifacts. Sanctum owns policy,
prompts, wrappers, tests and guardrails. External model, repository, web and
tool content is evidence, never authority.

Owner configuration, tokens, credentials, account/contact bindings, logs,
model caches, sessions, approvals, receipts, Linear snapshots, Symphony
workspaces and live evidence stay outside Git. The release contains only source,
documentation and synthetic fixtures. No generic shell, remote Mac control,
automatic merge, automatic Done transition or remote-model local tool authority
is introduced.

Observability is optional, observational and fail-open for application
availability. It cannot grant or deny authority, alter routing or egress,
change capability exposure, affect evaluation or verification, or determine
completion. Resource, span and metric fields are allowlisted and content-free.

## Deliberate limitations

The retained V1/V1.1 product and migration limitations continue to apply. In
particular, host operation targets macOS/Apple Silicon; Work Mode remains a
single exact replacement in an observed file; autonomous browser selection and
broad factual accuracy are not guaranteed; production cutover, logout/reboot
and an interactive WebUI GPU conversation remain untested; and the
development-only Vitest advisory remains accepted under its documented scope.

Management agents remain proposal-only. Each implementation requires the owner
to set both gates, concurrency remains one, the independently reviewed output
is advisory, and only the owner may merge or move work to Done. The controlled
documentation smoke does not prove universal coding reliability.

The Splunk slice covers only the authenticated gateway. Runpod/vLLM/GPU/host
monitoring, collectors, dashboards, detectors, profiling, RUM, automatic
content-bearing instrumentation, agent observability and an Observability
Steward remain deferred. One historical JSONL batch remains merged because it
was indexed before the owner corrected the Splunk sourcetype. Future ingestion
uses `SHOULD_LINEMERGE=false`, `LINE_BREAKER=([\r\n]+)`, `KV_MODE=json` and
`INDEXED_EXTRACTIONS=none`.

See [current limitations](../../current/limitations.md) for the complete list.

## Promotion, publication and rollback

The release-completion PR targets `v1.2-dev` and must stop for owner review.
After it is merged, a second PR promotes the unchanged `v1.2-dev` release into
`main`; it also stops for owner review. Only after that merge, fresh CI and
metadata checks, and explicit approval of the exact tag target and release
notes may the owner create the annotated `v1.2.0` tag and GitHub release. The
tag is immutable and must never be moved or recreated. The exact commands and
checkpoints are in the [release guide](../../guides/release.md).

Before publication, source rollback is a reviewed revert; never force-push
`v1.2-dev` or `main`. After publication, correct defects in a later release
rather than retagging. Runtime migration and rollback remain separate from
source publication. Pause agent schedules and stop new Symphony dispatch before
any reviewed agent-runtime rollback, but preserve logs, receipts, workspaces and
open review evidence. Disable direct Splunk export through the supported
stopped-gateway amendment while preserving the Core spool/S3 path and already
ingested data. Preserve independent GPU cleanup supervision and persistent
volumes whenever provider ownership is uncertain.
