# Architecture

The Mac owns authority: authentication, risk composition, privacy floors, exact disclosure tickets, local tool permissions, provider budgets and GPU ownership. Models reason over packets selected by that authority plane.

`gate/plugin/core.mjs` owns gate sessions, exclusions, revision-bound approval, routing and background results. `local-agent.mjs` invokes the authenticated OpenClaw agent, with loopback endpoint and local model checks. Calling a bare MLX endpoint would lose the tool loop; packaging preserves this distinction. Configurable ports remain loopback-only.

`gate/src/authority.py` validates signed requests and durable one-use nonces. `dispatch.py` composes risk/capability policy. `backends.py` contains tool-free reasoning transports, identity checks, context and cost limits. No failure silently authorizes another provider.

`lifecycle.py` owns locks, allocation intent, leases, capacity wait, readiness and confirmed deletion. `runpod.py` remains a narrow provider adapter. Mac-held credentials are not copied onto the GPU worker. A persistent cache volume survives compute termination. Independent cleanup is required before enabling automatic compute in a deployment.

Local semantic plugins call fixed Unix-socket brokers. The wrappers restrict their underlying service operations. Browser Guard, File Steward approval and reliability hooks remain separate boundaries. Reliability uses captured schemas, one bounded argument repair, provenance-preserving output and a narrow exact-answer verifier. It does not verify arbitrary prose.

The shared capability foundation projects actual owned-plugin registration, pinned adapter availability, captured schemas and current configured exposure into a versioned manifest. The build loads the compiled owned plugins, captures their registered tool definitions and compares those definitions with generated declarations and the reviewed schema capture; drift fails the build and never refreshes a hash. At runtime, configured plugin/adapter availability is recomputed before exposure. A capability proposal binds a reasoner, request revision, capability name, schema/policy digest and arguments, but carries no authority or egress grant. Authority and egress decisions are separate Mac-owned records. Egress binds the exact packet digest, capability digest, data classes, destination/model, purpose, scope, revision, expiry and one-use state; existing gate tickets and native approvals still enforce those decisions. Result envelopes preserve execution certainty, provenance, trust, truncation, repairs, verifier outcome and rollback mode. The verifier has only `VERIFIED`, `REJECTED` and `UNKNOWN`; unknown is never success. This layer does not add a remote tool loop.

The authenticated owner-only `/work` command is the installed Work Mode entry point. It creates a detached Git worktree on a bounded private APFS sparse image, then runs the accepted PRIVATE_LEAD reasoner as a proposal-only component. Every proposal reuses the shared capability manifest, Mac authority decision, semantic execution path, normalized result envelope and a distinct result-egress decision. Repository commands are fixed profile operations in a pinned, non-root OCI runner with a point-in-time `docker cp` workspace snapshot and no live host mount, network, home mount, Docker socket, inherited credentials or caller-selected command arguments. Source retrieval is available only through the Project 2 Source-First coordinator. A fresh host evaluator controls completion and at most one data-only reviewer may request revision or rejection. Task receipts are content-minimized, hash-chained and stored under the private prefix; they never grant authority.

The retained `router/` code supports historical deterministic privacy/escalation contracts for reliability. It is not a resurrected learned router or an AWS deployment requirement. Its mock escalation path must not be confused with the current gate's production transport.

The first observability slice manually wraps the authenticated gate request without entering any authority, routing, egress, capability, verifier or evaluator contract. Metadata-only Core events continue through the private spool and S3 path to Splunk Enterprise. Manual traces and a bounded custom metric set use the Splunk OpenTelemetry Node distribution for direct Observability Cloud ingest. Export is disabled without complete private configuration, and every observability failure fails open for application availability while remaining irrelevant to policy. Automatic content-bearing instrumentation, profiling, host/runtime metrics and collectors are absent.

## Qualified deployment boundary

MLX and Open WebUI use separate, prefix-owned environments. The gateway stays in the pinned repository npm tree. Both authenticated HTTP processing and interactive saved-chat acceptance exercised the real WebUI filter/pipe, exact audit disclosure, gateway and local model. For gate requests, the boundary filter selects legacy function-calling mode to prevent WebUI 0.11.1 from adding implicit built-in tools; explicit tool/feature requests remain denied. The signed private-80B worker completed a bounded real lifecycle with provider-confirmed deletion. The staged PRIVATE_LEAD release uses a distinct state directory and release identity; the independent launchd janitor attempts both mutually exclusive release namespaces on every sweep so one namespace cannot suppress cleanup of the other. These checks do not claim an interactive WebUI GPU conversation or a full logout/reboot test.
