# Qwen Code snapshot handoff for Work Mode

Status: source integration implemented; the [first live Qwen Code `/work` attempt](../history/v1.3/WORK-MODE-QWEN-FIRST-LIVE-ATTEMPT.md) failed during context compaction before host import. The isolated proof remains historical evidence, not a Work Mode completion receipt.

The [fourth isolated MoodLog proof](../history/v1.3/WORK-MODE-QWEN-CODE-FOURTH-ISOLATED-POC.md) established that Qwen Code 0.24.6 can make the required edits without a human editing mid-run. Its two paths were separate:

1. **Model path:** Qwen Code in a pinned, networkless container called a Mac-owned stdio broker. The broker reached the existing private 122B vLLM route through a loopback tunnel. The Sanctum gateway did not expose an OpenAI-compatible model endpoint.
2. **Coding-tool path:** Qwen Code's headless loop and tools ran inside that container on a copied workspace. The container had no live Mac worktree mount, network, host shell, home, credentials, or Docker socket. The Mac enforced an outer run deadline, workload limits, provider lease, and GPU cleanup. Qwen Code's turn, tool, and wall limits were additional bounds, not an authorization boundary.

## Mac-owned handoff implemented here

The new signed `worktree_qwen_export` operation freezes a clean, task-bound Work Mode workspace under the private evidence directory. It requires a passing protection check and the original candidate digest, copies ordinary files without following links, excludes `.git`, and records the task, protection, and baseline identities. It returns fixed private `qwen-input` and `qwen-output` paths. It does not run a model or expose a caller-selected host path.

The `worktree_qwen_run` route now copies `qwen-input` into a Docker volume with explicit non-root ownership, starts the pinned headless Qwen Code process, and copies final files to `qwen-output` only after the process exits. Neither directory is mounted from the Mac. A separate volume holds the broker and Qwen settings; its sole model route is the Mac-owned stdio broker forwarding `/v1/models` and `/v1/chat/completions` to the configured private lead loopback tunnel. The container has no network, Mac worktree mount, Docker socket, home or credentials. Raw goal, model requests, tool trace and source-bearing output stay in the private task evidence directory outside Git. The fixed Qwen prompt and permission flags are not authority controls.

The image recipe pins a Node base digest, Qwen Code 0.24.6, and its npm dependency lock. The stopped-gateway Work Mode upgrade builds it locally, records its exact image ID in the private profile, and the runner checks that ID before use. The runner also checks the existing fixed-command image separately. A source upgrade is required before selecting this engine; an old installed image/profile cannot silently satisfy it.

The signed `worktree_qwen_import` operation accepts only that fixed output for the same task. It rejects symlinks, special files, deleted files, new directories, `.git`, protected or disallowed paths, stale workspace state, oversized files or diffs, and an unchanged candidate. It builds a canonical patch and passes it through the existing Mac patch authority. The original candidate digest is checked again under the patch lock; a changed workspace fails closed. An attempt marker prevents replay. The receipt identifies the accepted output and patch digests, changed paths, workspace generation, and authority decision. Original file modes are preserved; new files use the patch authority's mode. No container output directly mutates the task worktree.

These operations are host-only worker routes requiring the existing owner Work Mode authorization. They are not model-visible capabilities. A newly registered private profile selects `engine: "qwen_code"`; owner task text cannot select it. The task command, protected oracle, fixed test commands, evaluator, separate data-only reviewer, receipt chain, and Human Review remain Sanctum responsibilities. The Mac records starting commit and private baseline ordinary-test output before Qwen starts. A Qwen final message cannot complete a task: import, ordinary tests, protected acceptance, stable diff, reviewer `ACCEPT`, and confirmed GPU cleanup are required.

## Limits and failure behavior

The reviewed Qwen profile fixes 48 model requests, 40 tool calls, a 20-minute Qwen wall limit, a 40-minute Mac task limit, a 45-minute GPU lifecycle ceiling, a $10 run ceiling, and zero retries. The Mac broker independently caps requests and responses, inference at 900 seconds, one workload, and the configured provider identity/price. The Mac task timer covers baseline, coding, evaluation and review. The worker has a separate bounded deadline and cleanup grace. Qwen cannot raise any limit through its prompt or settings. A failed, unchanged, oversized, protected, stale, or uncertain output stops without a completion receipt. The private trace and final container snapshot remain available for diagnosis. The task closes private lead compute before reporting a terminal result; the independent janitor remains loaded.

The [second live MoodLog attempt](../history/v1.3/WORK-MODE-QWEN-SECOND-LIVE-ATTEMPT.md) also failed before host import: the private model ignored a text-only compaction request and returned a coding-tool call. The proposed Mac-side deterministic compaction fallback has offline contracts only. The next paid MoodLog run requires a separate owner-approved window of at most 45 minutes and under $50, with no automatic retry. Before that run, verify the preserved clean candidate commit and exact protected oracle, install through the supported stopped-gateway amendment, run doctor, and confirm provider price, capacity, janitor and no existing allocation. Afterward, independently verify ordinary and protected tests, browser save/reload/newest-five/clear behavior, private trace and provider-side zero compute/leases/requests. A full result needs both that live evidence and the owner's Human Review.

## Reproducible setup after source review

1. With the gateway stopped and no managed allocation or lease, run `python scripts/upgrade_work_mode.py --prefix /absolute/private/prefix --apply`, then `make doctor PREFIX=/absolute/private/prefix`. The upgrade builds and records both pinned images. It preserves registered private task profiles and their protected input bindings.
2. Create a new private staging directory and a clean private MoodLog candidate at the preserved starting commit. Register a new profile through `scripts/configure.py` with `work_profile` fields `name`, `copy_from`, `repository`, and `engine: "qwen_code"`. Copy from the existing single-stage `moodaccept` profile so its fixed commands and protected oracle are retained. The command rejects inherited stages, a disabled reviewer, an unreviewed image, or a profile outside the private prefix. Run doctor after the stopped-gateway amendment.
3. Start only that reviewed profile via authenticated `/work start PROFILE -- GOAL`, using the preserved private MoodLog task text. The task starts a fresh isolated worktree and records baseline test output. Inspect `/work result TASK_ID` and the owner-only ledger/trace; then use `/work end` after review. The exact raw prompt, source bodies, output files and account bindings remain private.

Open WebUI is only the current command surface. Switching the general interface to Qwen Code's TUI or Web Shell is a separate project and does not change this coding engine boundary.
